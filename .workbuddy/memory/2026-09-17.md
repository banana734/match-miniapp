## 新增：全页面背景图（房间插画）
- 需求：用户把房间水彩插画放到 `image/home.jpg`，要求「所有页面都当背景」（AskUserQuestion 选定）。
- ⚠️ **踩了个大坑，差点做错**（结论已写进 MEMORY.md）：
  - 第一反应是给全局 `page { background-image: url('/static/x.jpg') }`。实测发现**这条路根本不通**：
    1. 小程序 **WXSS 的 background-image 不支持本地文件路径**（只能用 base64 或网络图）。uni-app 会把路径原样写进 WXSS（`url("static/home-bg.jpg")`），而且 **`dist/dev/mp-weixin/static/` 根本没生成**，图根本没进产物。
    2. 就算能显示，`page` 的 `background-size: cover` 是**按「整页高度」算的**——页面一长（资料表单好几屏），图片会被放大成一团模糊的局部，每个页面糊的程度还不一样。
  - 还试算了 base64 方案（用系统 Python 的 Pillow 压了几档：原尺寸 q65→343KB、1400宽 q72→224KB、1100宽 q75→162KB，base64 后还要 ×1.33），但**因为第 2 条没解决而被否掉**。
- 最终方案：**固定定位的 `<image>` 背景层**
  - 全局样式（common.scss 的 `page{}` 之后）加 `.page-bg { position: fixed; top/right/bottom/left: 0; z-index: -1 }` 和 `.page-bg-img { width/height: 100% }`。
  - `z-index: -1` 是特意选的：排在内容之下；万一某些环境不认负值，失败表现只是「图不显示」，**不会盖住内容**（安全失败）。
  - 15 个页面**每个模板最外层加一行**：`<view class="page-bg"><image class="page-bg-img" src="/static/home-bg.jpg" mode="aspectFill" /></view>`。`mode="aspectFill"` 负责裁剪铺满。
  - 图片放 `src/static/home-bg.jpg`（原图 `image/home.jpg` 保留当源文件）。
- ⚠️ **另一个坑**：`src/static/` 是**这次新建的目录**，**正在跑的 dev watcher 不会扫描到新建的 static 目录**，所以 `dist/dev/mp-weixin/static/` 一直不生成。解决办法：① 手动 `cp` 一份进 `dist/dev/mp-weixin/static/`（本次这么做的，立刻可用）；② 或者重启 `npm run dev:mp-weixin`（全量构建会正确拷贝——已用 `npm run build:mp-weixin` 验证，`dist/build/mp-weixin/static/home-bg.jpg` 728KB 正常生成）。
- 验证：15/15 页面的 `.vue` 各含 1 处背景层；编译后 15/15 的 wxml 都有 page-bg；`app.wxss` 含 `.page-bg`/`.page-bg-img`；`common/assets.js` 里 `_imports_0 = "/static/home-bg.jpg"` 解析正确；dev 产物图片已补齐。

## 微信小程序背景图的三条硬知识（复用）
1. WXSS `background-image` **不支持本地路径** → 要么 base64，要么网络图，要么改用 `<image>` 元素。
2. `page` 的背景 `cover` 按**整页高度**算，不按视口 → 长页面必糊；要「固定壁纸」效果得用 `position: fixed` 的层。
3. 运行中的 dev watcher **不会发现新建的 `src/static` 目录**，新增静态资源目录后要么重启编译进程，要么手动补进 dist。

## 修匹配页搜索：按「用户填的内容」过滤，不再匹配题目名
- 用户报的问题：**搜什么都返回全部卡片**。他举例「想找一个叫小孩的用户，但每张卡片都有一个叫孩子性别（的题目），所以全部都会显示」。
- 根因：`match.vue` 的 `getCardSearchText()` 把 `line.label`（题目名）和 `item.badge`（系统标记）也拼进了搜索文本。卡片的 `preview`/`details` 结构是 `{ label: 题目名, value: 单个答案 }` 或 `{ label, items: [多个答案] }`，题名每张卡都一样 → 一搜题名就命中全部。
  - 顺带确认字段来源（`server/routes/match.js`）：`title = profile.name`、`subtitle = 地区 / 学校·专业`（都是用户填的）；`badge` 是 `'家庭'` 或 `'骨干成员'/'普通成员'`（**系统生成，不是用户填的**）。
- 修法：`getCardSearchText()` 里**删掉两处 `if (line.label)` 和一处 `if (item.badge)`**，只保留 title / subtitle / `line.value` / `line.items`。其余逻辑（大小写不敏感、空关键字不过滤）不动。注释里写清了「为什么刻意不收 label / badge」，防止以后又被加回去。
- **验证方式（值得复用）：拉真实接口数据做新旧对比回归，而不是只看代码。**
  `curl -s "http://127.0.0.1:3000/api/match/list?role=mentor" -o pool.tmp.json`（10 张真卡片），然后在 node 里把新旧两版拼串逻辑各写一份，对比命中数：
  | 搜索词 | 旧 | 新 |
  |---|---|---|
  | 孩子性别（题名） | 10 张 | **0 张** |
  | 家长称呼（题名） | 10 张 | **0 张** |
  | 家庭（badge） | 10 张 | **0 张** |
  | 辅导（真实答案词） | 10 张 | **2 张**（只有真填了的） |
  | 小孩（真实姓名） | 1 张 | **1 张**（仍然搜得到） |
  注意「年级」新旧都是 10 张 —— 那是因为年级答案本身就是「小学一年级 / 小学二年级」，**属于真实数据命中，不是 bug**。判断时要区分「命中题名」和「命中答案里恰好含这个词」。
- 产物校验：`dist/dev/mp-weixin/pages/match/match.js` 里打印出编译后的 `getCardSearchText`，确认已无 `line.label` / `item.badge`。用完删掉 `pool.tmp.json`。

## 查清「搜『小孩』搜不到」的原因（重要，是设计而非 bug）
- 用户现象：匹配页搜「小孩」返回空，但「我的」页测试账号列表里明明有「小孩」这个人。

- **真正原因：卡片没被搜掉，是被 `visiblePool` 隐藏了。**
  `src/pages/match/match.vue` 的 `visiblePool` 会把「已在自己 pending/formal 列表里」的卡片从池子里剔除（避免重复申请）：

  查库结果：两个导师账号已经拿走了「小孩」这张卡 ——

- 教训：以后遇到「池子里少了一张卡」，先查 `trial_records` 里这张卡在本账号名下是不是 pending/formal，别一上来就怀疑搜索逻辑。
