## 修复：重置/切换账号后，资料表单还显示上一个人的资料
- 根因：`resetLoginState`（store/user.js）清了登录态和缓存，但**没清 `profile`（共用资料字段池）**。资料表单页（family-data/mentor-data）初始化时直接从 `userStore.profile` 取值，且 onShow 只在后端「有」资料时才回填覆盖——新账号查不到资料时表单就保持本地残留 → 重置后显示"未填写完成"但能看到上一个人的资料。
- 改动：
  - `src/store/user.js`：把空资料对象抽成 `createEmptyProfile()`（初始与重置共用）；`resetLoginState` 增加清空 profile + profileCancelled；新增 `clearProfile()` 导出。
  - `src/pages/My/My.vue`：`switchToAccount` 切换账号后异步请求 `/profile/detail?openid=&role=`——后端有资料就 `updateProfile + completeProfile` 回填，没有就 `clearProfile()` 清残留。
- 经验：本地 store 的 profile 是跨账号共享的内存池，任何"换身份"操作（重置/切换/重新登录）都要同步处理 profile；表单页只在后端有资料时覆盖，查不到时以本地为准，所以换身份必须主动清。
- 编译通过（build + dev 均含 clearProfile / profile/detail）。

## 修复（续）：重置账号后表单仍显示上一个人资料 —— 真正根因是模块级 form 只初始化一次
- 用户反馈上一轮修复无效。排查发现 store 的修复确实在产物里（store/user.js 含 clearProfile），真正根因另有其处：
- **根因**：mentor-data / family-data 的表单是**模块级 `reactive({...})`，从 `userStore.profile` 取值**。小程序页面模块整个 app 生命周期只执行一次，`reLaunch` 不会重新执行模块代码 → form 一直保留首次加载时的旧值。onShow 的后端回填只在「后端查得到资料」时才覆盖；重置后的新账号查不到 → 表单保持上一个人的旧值。
- **修复**：两个页面各加一个 `onLoad` 钩子（先 import onLoad），回调里用现成的 `syncFormFromProfile(userStore.profile)` / `applyProfileToForm(userStore.profile)` 重刷表单。onLoad 只在新建页面实例时触发（物理返回不触发、草稿不丢），且先于 onShow 的后端回填，顺序正确。
- 经验：**uni-app 小程序里，模块级从 store 初始化的响应式状态，在 reLaunch/重新登录后不会自动刷新；「每次新开页面需要最新值」的初始化必须放 onLoad，不能依赖模块顶层代码。**
- 编译通过（build + dev 两页 js 均含 onLoad）。
